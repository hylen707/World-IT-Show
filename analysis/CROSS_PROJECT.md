# EC4–EC5 synthesis protocol

Companion repository: [CES2025 / EC5](https://github.com/hylen707/CES2025).

EC4 presently centers on material-to-device inference in a graphene company report. EC5 must retain its own source-grounded question. A useful common axis is **how a technology claim becomes verifiable**, rather than asserting that two events demonstrate a market trend.

| Comparable dimension | EC4 operation | EC5 intake rule |
| --- | --- | --- |
| Claim unit | One consequential statement with exact location | Use one equivalent statement, not a slide count |
| Mechanism | Material property → manufactured film → appliance task | Trace the actual system chain in EC5's evidence |
| Evidence boundary | Paper result, vendor statement, report assertion, model | Preserve the same distinctions |
| Missing data | Unknown measurement, version, contribution | Keep `null`/pending; do not reward more marketing detail |
| Counterargument | Version mismatch, process improvement, attribution lineage | Identify domain-specific alternatives |
| Validation | Proposed matched task, not executed | Separate actual results from proposed tests |
| Personal agency | Still requires student verification | Do not infer ownership from repository access |

No event-year comparison, geographic superiority, company ranking, participant impact, or cross-event longitudinal trend is supported merely by having two repositories. The student can later write a reflection comparing a specific changed belief across verified originals; the present repository does not invent that reflection.
